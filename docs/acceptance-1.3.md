# OrbitWheel 1.3 本地验收

日期：2026-10-04。分支：`codex/settings-usability-1.3`，实施基线为已合并 1.2 的默认分支提交 `f7f3f15`。产品版本为 `1.3`，程序集和文件版本为 `1.3.0.0`。本次范围为 [#4](https://github.com/V0idream/OrbitWheel/issues/4) 的设置窗口可用性。

## 实施结果

- 设置外壳和内容区域随窗口伸缩；卡片保持至少 700 个 96 DPI 逻辑像素的可读宽度，超过视口时使用原生横向、纵向滚动。
- 六个页面均可访问全部控件和说明文字；小屏幕上的侧栏也可滚动访问“关于”。页面名、动作表格和快捷键区域按可用宽度调整，表格行高、表头及最小列宽随 DPI 缩放。
- 标准最小外部窗口为 `1080×700`（96 DPI）。支持自动缩放；工作区小于标准最小尺寸时，以工作区宽高为上限，保留滚动访问。打开窗口时也会限制初始尺寸。
- 切换动作页面、设置页面、增删页面和关闭窗口前，先提交正在编辑的单元格。保存按实际加载的动作页面写入，避免旧页面的未提交输入丢失或写到新页面。
- 只有启动选项实际改变时才同步启动项；其他编辑仍走生产自动保存路径。

## 本机自动验收

环境：Windows 11 `10.0.26300`，Windows PowerShell 5.1 / .NET Framework 4.x。本机真实显示 DPI 为 168（175%）。测试实例化真实 `SettingsForm`，设置窗口位于屏幕外，不启动生产 `OrbitContext`。

| 验收项 | 结果与证据范围 |
| --- | --- |

| 100% / 150% / 200% 控件缩放 | 通过。三档缩放分别检查标准最小尺寸、1920×1040 和 1366×728 工作区，合计 54 个页面场景。使用 WinForms `Control.Scale`，并按宿主 GDI DPI 调整字体点数，使文字物理大小对应目标缩放。未更改 Windows 显示设置。 |
| 高缩放兼容工作区 | 通过。另检查 960×520 逻辑工作区的六个页面，模拟 DPI 兼容模式下缩小的可用工作区。 |

设置回归原始证据：`dist/tests/settings-82463bbe640940e796e202644ec4696e/geometry.log`。同目录保存 48 张 `DrawToBitmap` 控件渲染图，覆盖三档缩放的标准最小尺寸和笔记本工作区、兼容工作区及本机 175% DPI。已复核动作表、快捷键和高级页的代表图；这些图属于原生控件离屏渲染，不是桌面截图或真人拖动证据。

测试配置使用独立目录，自动保存没有写入用户配置；未更改启动项、注册全局快捷键、执行配置动作或改变 Windows 显示缩放。

## 发布前仍需人工验收

真实 Windows 显示缩放 100%、150%、200% 的六页交互验收尚未完成。控件缩放和 175% 本机几何检查不计作这三档的人工通过证据。

每档显示缩放分别执行：

1. 打开设置，缩至系统允许的最小尺寸；逐页检查常规、页面与动作、外观效果、快捷键、高级、关于。
2. 用滚轮、滚动条和键盘访问超出视口的内容，确认右侧目标路径、底部提示、添加/删除页面及“关于”可达。
3. 编辑页面名和六个扇区的名称、类型、目标；在单元格仍处于编辑状态时切页，再返回检查。录制快捷键并修改模式、外观和手势选项。
4. 关闭设置后重新打开，退出应用后重新启动，确认所有更改自动保存；放大窗口后检查卡片伸展和滚动条变化。
5. 记录显示器分辨率、缩放、实际最小外部尺寸及结果。多显示器或工作区较小时，补查窗口打开位置和滚动可达性。

CI 和 Release 构建 job 已加入设置回归。本文不把本机检查计作远端 CI 或正式发布结果。

## 发布流程复核

首轮 PR CI `37180237637` 的构建、打包和动作可靠性检查通过，设置回归的最小尺寸断言失败。无桌面 runner 的原生最大可跟踪窗口尺寸小于测试声明的工作区，WinForms 会进一步限制 `MinimumSize`。修正后，窗口和测试均显式考虑 `SystemInformation.MaxWindowTrackSize`；本机再次通过 66 项设置检查，证据目录为 `dist/tests/settings-4dec7c6424ad4bb89a74942524189793`。远端重跑结果以 Actions 为准。

后续远端检查确认 WinForms 会再次按真实桌面限制尺寸，因此最小尺寸及放大后的滚动条检查按实际窗口约束和视口验证。运行 `37180519851` 在通过 100% 编辑保存后发现 150% 下外壳锚点仍保留未约束的缩放边界；外壳改为 `DockStyle.Fill` 配合窗口内边距，保证真实客户区发生系统约束时仍完整排布。修改后本机 66 项检查再次通过，证据目录为 `dist/tests/settings-5612a45563ef471ab4e399a05f1f7ebd`。
