## 并发读取结论

旧代码每次读取等待保存互斥锁最多 250 毫秒；连续原子写入与落盘可能让读取超时，这和配置 JSON 是否完整无关。读取现在打开带 `FileShare.ReadWrite | FileShare.Delete` 的文件快照，不竞争保存互斥锁。Windows 替换期间短暂打开失败最多等待 90 毫秒重试 I/O，坏 JSON 不重试、不重置。写入继续在互斥锁内验证修订、落盘并原子替换。

新增“另一线程持有写锁时读取仍成功且小于 250 毫秒”的回归，配合真实进程连续写入/完整快照一致性回归。新方案首次无重试时发现 `FileNotFoundException`，据此增加有限 I/O 重试；不是简单放宽测试断言，也不是只依赖重跑通过。
