# OrbitWheel 2.1 设置分步修复计划

GitHub 总跟踪：[Issue #10](https://github.com/V0idream/OrbitWheel/issues/10)。本计划对应 [HIG 审计报告](settings-hig-audit-2.1.md) 的全部 16 项发现。当前已实施本地代码修复，正在完成候选验证；人工验收缺口与实际证据见 [2.1 验收记录](acceptance-2.1.md)。下表保留原依赖顺序与关闭条件。

## 执行顺序

| 阶段 | Issue | 分步建议 | 完成标志 |
| --- | --- | --- | --- |
| 1. 配置恢复 | [#11](https://github.com/V0idream/OrbitWheel/issues/11) | 区分读取、写入、冲突状态 → 增加重试/保留编辑/确认放弃的退出路径 → 读取恢复清除对应故障 → 降低普通保存提示的强调程度 | 冲突时可安全退出；本地内容可保留；外部有效配置不被覆盖；相同修订恢复不残留读取警告 |
| 2. 实际生效 | [#12](https://github.com/V0idream/OrbitWheel/issues/12) | 先保障热键失败恢复旧绑定 → 定义配置修订与主程序实例关联的状态回传 → 回传热键/启动项/手势结果 → 在设置行显示离线、成功和失败状态 | 新键冲突仍保留旧键；保存不等于已生效；陈旧状态不被误用 |
| 3. 快捷键录制 | [#13](https://github.com/V0idream/OrbitWheel/issues/13) | 在 #12 契约稳定后分离当前值与候选值 → 显式开始录制 → 处理取消/导航/候选校验 → 处理在线主程序热键 → 完成真实键盘矩阵 | 聚焦/复制不改配置；Esc 取消；Tab 可进出；有效候选只提交一次；录制不意外召出轮盘 |
| 4. 动作编辑 | [#14](https://github.com/V0idream/OrbitWheel/issues/14) | 在 #11 的恢复契约上实现候选提交/取消 → 按类型验证与提示 → 同步页面及扇区摘要 → 完善选择器、删除边界和电源动作说明 → 保留展开/滚动/焦点上下文 | 取消选择保留原有效动作；名称即时一致；六个槽位不重排；未知值不显示虚假选项 |
| 5. 信息组织 | [#15](https://github.com/V0idream/OrbitWheel/issues/15) | 在 #12/#14 状态与编辑交互稳定后明确页标题与输入分组 → 补模式/取消/翻页说明 → 补版本/反馈/许可证/复制路径 → 修正条件文案和效果说明 → 决定 P3 是否延期 | 信息符合实际状态；关于信息完整；README 方位与轮盘一致；P3 有明确决定 |
| 6. 可访问性 | [#16](https://github.com/V0idream/OrbitWheel/issues/16) | 在交互稳定后补标题/搜索/列表/重复动作语义 → 补用途与禁用原因 → 检查焦点和状态播报 → 完成真实键盘/Narrator → 按需要补跨区导航 | 必要操作键盘可达；对话框可安全取消；辅助技术可理解状态；保存不反复打断阅读 |
| 7. 最终验收 | [#17](https://github.com/V0idream/OrbitWheel/issues/17) | 从最终提交重新构建 → 契约与动作回归 → 定位并发互斥超时 → 真实热键/启动项/手势 → 选择器/托盘生命周期 → Narrator/系统主题/DPI/多显示器 | 有可追溯的最终提交、包与实际证据；未完成项明确记录 BLOCKED/PARTIAL |

阶段 1 和 2 的逻辑可以独立设计；建议依表中顺序合入，避免多个变更同时重写 MainWindow。每阶段以相关 Issue 的关闭条件为准，不用完成代码编写代替运行验收。

## 修复与验证边界

- 保留配置格式、动作类型、六个扇区绑定和 WinForms 托盘/轮盘职责。
- 保留原子保存、修订校验及坏文件保护；普通设置继续自动保存。
- 当前源码构建及隔离 WinUI/WinForms 基线回归通过；后续需要基于最终变更重新验证。
- 已复现的配置冲突关闭受阻、名称摘要滞后和读取恢复警告残留，不能只靠视觉调整关闭。
- 录制的具体按键路由、全局热键、Narrator、真实系统主题/DPI 等仍需实际操作证据。
- 关机/重启动作补后果说明；测试不实际执行电源动作，新增执行确认另作产品决定。
- 创建 Issues 与完成修复验收均不自动授权发布。
