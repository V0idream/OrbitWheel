# OrbitWheel 2.1 设置 HIG 审计

审计日期：2026-10-04。源码基线：`OrbitWheel` 分支，`6a3a65cdd1bc9029b2b839954a65cff0d02f34d8`；产品版本仍为 **2.0**。本文是 2.1 的审计与修复候选清单，未修改产品代码、版本或发行状态。

结论：WinUI 原生控件、自动保存和共享配置保护已具备基础，但设置体验还存在恢复路径、快捷键录制、生效反馈和上下文一致性问题。本轮记录 **16 项：P1 3 项、P2 10 项、P3 3 项**。优先级是本项目的审计判断，不是官方规范给出的评级。代码与自动化审计完成；人工可访问性和系统环境验收为 PARTIAL。

## 规范与适用范围

以 [Apple HIG：Settings](https://developer.apple.com/design/human-interface-guidelines/settings) 的合理默认值、精简设置、符合预期的入口、尊重系统设置和任务上下文原则为通用依据。已读取 Apple 官方文档的 [JSON 内容](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/settings.json)。本软件是 Windows 应用，macOS 的菜单和快捷键要求不直接适用。

平台实现参考 [Windows 应用设置指南](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings)、[键盘可访问性](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/keyboard-accessibility)、[可访问性检查表](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessibility-checklist) 和 [对话框指南](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/dialogs)。本轮采用相关分组、就地反馈、键盘可达、可恢复操作等原则；后文中的具体方案是针对当前代码提出的建议。

审计覆盖当前发布路径的六个 WinUI 设置页、应用/文件夹选择器、删除和重新加载对话框、托盘入口、设置单实例、主程序接收配置及设置对轮盘行为的影响。`legacy/WinFormsSettings.cs` 不进入生产包，只作为历史对照；旧窗口的验收不能替代 WinUI 验收。

此窗口本身就是设置编辑器，所以 `NavigationView.IsSettingsVisible=False` 不构成缺陷。六个导航项、未采用 Community Toolkit SettingsCard、900 DIP 的内容上限、没有用户可选的设置窗口主题，也不单独判为违规。无需为遵循 HIG 添加主题、动画、透明度等重复的系统偏好开关。

## P1：优先处理

### P1-01 保存冲突把用户困在当前页

**证据：已用当前源码的隔离 WinUI 副本复现。** 编辑名称后由另一进程写入配置，保存被拒绝。发送真实窗口 `WM_CLOSE` 后窗口仍打开；选择其他导航页也回退到原页。窗口保留编辑是正确的，但唯一界面恢复入口是“重新加载”，它会丢弃本地编辑。

位置：`MainWindow.xaml.cs:46–48, 61–63, 76–90, 112–132`。不仅版本冲突，持续写入失败也会进入无法正常关闭的路径。当前未提供“重试保存”“复制/导出未保存内容”“放弃修改并关闭”等选择。

建议：保持拒绝覆盖保护；关闭时提供明确的恢复选择，允许取消关闭、重试，或确认放弃后关闭；冲突时提供保留本地编辑的复制/导出路径。不要静默覆盖外部文件。

验收：外部冲突及写入失败时，取消保留编辑；保留/导出内容后可退出；确认放弃可关闭；磁盘上的外部有效配置不被覆盖。

### P1-02 快捷键录制没有明确的开始、完成和取消状态

**证据：源码确认。** 只读 TextBox 获得焦点后，所有进入该处理器的非修饰键直接更新配置并自动保存。用户仅因键盘导航进入控件，或者想复制现有组合键，也可能触发重绑定；处理器没有录制开关、取消分支或候选校验。

位置：`MainWindow.xaml.cs:311–333`。Tab、Esc、Enter、复制组合键和系统保留组合键的真实事件路由还需桌面实测；本轮没有把“Tab 一定被截获”列为已复现事实。

建议：显示当前快捷键，使用“更改快捷键”进入录制；显示录制状态；Esc 取消并保留原值；导航键保留正常语义；确定有效候选后保存。键名使用用户熟悉的显示形式，如“空格键”。

验收：仅聚焦和复制不修改配置；Tab/Shift+Tab 可进出；Esc 不保存；有效录制一次完成；主程序正在运行时不会在录制过程中意外召出轮盘。

### P1-03 “已保存”缺少实际生效结果，快捷键失败还会失去旧绑定

**证据：源码确认。** 设置只报告文件保存成功；没有接收主程序运行和注册结果的通道。快捷键失败只发托盘气泡，启动项失败只记日志；手势失败会回写关闭状态，但失败原因仍只在气泡中。`HotkeyWindow.Set` 在尝试新注册前注销旧绑定，因此新键冲突时原先可用的键也不再可用。

位置：`MainWindow.xaml.cs:87–88, 163–169, 326`；`OrbitWheelLite.cs:129–132, 1736–1776`。

建议：区分“配置已保存”“主程序未运行”“已生效”“应用失败”，在相关设置行显示可操作原因。新快捷键验证失败时保留或恢复旧的有效绑定。启动项以实际注册结果回显。

验收：主程序离线时明确等待应用；注册冲突时原键仍有效，设置页持续显示冲突；启动项写入失败时不将开启状态当作已生效；手势失败在开关旁显示原因。测试使用专用热键和隔离/可恢复的启动项环境。

## 已有能力及应保留的边界

- 两个开关采用原生 ToggleSwitch；手势和开机启动默认关闭；预置页面可直接使用。
- 六个设置页采用 NavigationView、ScrollViewer 和原生输入控件，动作只用一层 Expander；具备宽度约束和窄窗口导航收起。
- 输入延迟 500 ms 自动保存，切页/关闭前尝试提交；无需增加普通“应用/保存”按钮。新反馈应区分文件保存与主程序生效。
- 原子替换、跨进程互斥、修订校验、坏文件保护有效；不可为了避免错误提示删除这些保护。
- 文件/文件夹选择器关联真实 HWND；删除和重新加载对话框均有取消；未将执行命令或电源动作当作配置预览执行。
- 扇区编辑顺序与轮盘命中算法一致，双进程回归验证未重排。保持现有配置格式、动作类型及 WinForms 托盘/轮盘职责。
